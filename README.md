# SushaIPTV Orsay SmartHub

Русский | [English](README.en.md)

SushaIPTV Orsay SmartHub (ранее SushaTV) — IPTV-виджет для Samsung Smart TV Legacy / Orsay. Целевая модель проверок — Samsung UA32J4303 с прошивкой T-N14MJUABC-1080.0. Это отдельный проект; он не заменяет SushaMedia Orsay SmartHub (ранее SushaMegaTV).

## Возможности и состояние

Виджет содержит три вкладки с пользовательскими плейлистами: FILMS, kinofilm и kino-plus. Стрелки влево и вправо переключают вкладки, вверх и вниз выбирают запись. OK запускает поток, повторный OK разворачивает видео, Return возвращает список. VOL+/VOL− и Mute управляют звуком; CH+/CH− переключают записи текущего плейлиста.

Начиная с версии 0.110 сборка включает снимки трёх плейлистов в ZIP. Для просмотра ей не нужен компьютер, но потокам нужен интернет. Списки обновляются при новой сборке и синхронизации. **Версия 0.110 проверена локально в браузере; переименованная версия 0.111 и автономное воспроизведение на физическом телевизоре ещё не проверены.** По состоянию проверки 2 ноября 2026 года на целевом телевизоре была установлена 0.109, использующая локальный сервис плейлистов. Подробности — в [отчёте о проверках](TESTING.md).

Для совместимости установленного виджета технический идентификатор Apps Sync `SushaTV` сохранён; название репозитория можно использовать как `sushaiptv-orsay-smarthub`.

Устройство виджета, плейлистов и сервера синхронизации описано в [архитектуре](docs/architecture.md).

QR-код Telegram-канала `@AIShtokov` открывается кнопкой INFO на пульте или кнопкой Telegram в шапке. Физическая кнопка INFO на целевом телевизоре ещё не проверена.

## Сборка

Нужны Python 3.9+, `curl` и три M3U-файла. Ниже создаются отдельные временные каталоги; команда не изменяет приложение на телевизоре.

```sh
PLAYLISTS_DIR="$(mktemp -d)"
SYNC_DIR="$(mktemp -d)"
SYNC_IP="192.168.1.20"  # пример: замените на адрес компьютера в локальной сети

curl -fL --max-time 60 -o "$PLAYLISTS_DIR/films.m3u" \
  'https://raw.githubusercontent.com/Dimonovich/TV/Dimonovich/FREE/FILMS.m3u'
curl -fL --max-time 60 -o "$PLAYLISTS_DIR/kinofilm.m3u" \
  'https://raw.githubusercontent.com/slava-67/TV/refs/heads/IPTV/kinofilm.m3u'
curl -fL --max-time 60 -o "$PLAYLISTS_DIR/kino-plus.m3u" \
  'https://raw.githubusercontent.com/slava-67/TV/refs/heads/IPTV/kino-plus.m3u'

python3 tools/build-widget.py \
  --playlists-dir "$PLAYLISTS_DIR" --output "$SYNC_DIR/widget.zip" \
  --server-dir "$SYNC_DIR" --server-ip "$SYNC_IP"
```

Сборщик проверяет ZIP и создаёт в `SYNC_DIR` файлы `sushatv.zip` и `widgetlist.xml`. Обе копии пакета получают права `0600`; запустите сервер от имени их владельца или отдельно настройте доступ. Сформированный manifest содержит **только SushaTV**. Плейлисты и готовый ZIP могут включать ссылки, которые не следует публиковать без проверки. Обновление списков требует повторной сборки.

## Установка через Apps Sync

Перед синхронизацией сохраните действующий manifest и пакеты установленных приложений. Если на телевизоре есть SushaMegaTV или другие пользовательские виджеты, используйте общий manifest с их записями и убедитесь, что каждый ZIP доступен по своему адресу. Одной записи в XML недостаточно. Не подменяйте их однопрограммным manifest из сборки SushaTV.

`tools/widget-server.py` отдаёт только `widgetlist.xml` и `sushatv.zip` указанному IP телевизора. Для совместной синхронизации нескольких приложений нужен сервер, который также отдаёт остальные пакеты. Убедитесь, что выбранный IP назначен компьютеру, порт свободен и прежние приложения останутся доступны. На проверенной прошивке после входа как `develop` доступны Samsung Apps → Options → IP Settings и Apps Sync; названия и доступность пунктов могут отличаться.

При запуске `tools/widget-server.py` или дополнительного сервиса плейлистов необходимо явно указать `--bind` и `--tv`. Для сборки обязателен IPv4-адрес `--server-ip`: адреса из сети автора по умолчанию не используются.

После синхронизации откройте виджет, проверьте вкладки, изображение, звук и пульт, затем перезапустите телевизор и повторите проверку. Для отката сохраните предыдущий ZIP и manifest. Инструкция для агента — в [AGENTS.md](AGENTS.md).

## Проверка проекта

```sh
node --check app/app.js
node tests/test-remote.js
python3 -m unittest discover -s tests -v
git diff --check
```

Сетевые тесты создают локальные loopback-сокеты. Их результаты и браузерная проверка не подтверждают установку и воспроизведение на физическом телевизоре.

GitHub Actions также запускает Ruff и проверку синтаксиса ES5. Для дополнительного браузерного теста QR нужен [agent-browser](https://github.com/vercel-labs/agent-browser) с установленным браузером; путь к своей обёртке можно указать через `AGENT_BROWSER`.

## Ограничения

Состав и доступность записей контролируют владельцы источников. Некоторые ссылки могут требовать авторизации, специальных заголовков, определённого региона или неподдерживаемого телевизором кодека. Виджет не передаёт пользовательские заголовки M3U и не обходит ограничения источников. Не все записи являются рабочими потоками. Лицензия проекта не указана; плейлисты и контент предоставляются третьими сторонами.
